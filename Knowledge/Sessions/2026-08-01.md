### Decisions
- **Ловушка деактивации владельца.** `MergeTarget.ExecuteMergeDirectly` деактивирует исходное животное (`animal.gameObject.SetActive(false)`, `MergeTarget.cs:124`) строкой ниже после `Merge?.Invoke(...)` (`:113`) — компонент, ВЛАДЕЮЩИЙ `CheetahMergeAttribute`, выключается через миллисекунды после `Apply`. Три следствия для любого будущего visual merge attribute: (а) корутина бросит исключение на неактивном GameObject; (б) очистку нельзя вешать на `OnDisable` — она убьёт эффект мгновенно, только `OnDestroy`; (в) `UniTask.Yield(PlayerLoopTiming.Update, ct)` и `UniTask.Delay` крутятся на player loop и переживают деактивацию — это и есть рабочее решение.
- **Асинхронная последовательность без изменения синхронного API.** Добавление `ApplyAsync` в базовый класс расползлось бы на 7 файлов и сломало синхронный контракт `MergeCommand.Execute() : bool`. Паттерн — «sync-фасад + `.Forget()`», прецедент `DeathSpiritSpawner.OnDied`. Подробности → [[2026-08-01-merge-sweep-glow]].
- **[CRITICAL, найдено ревью и исправлено] Overlay-материал нельзя снапшотить как «оригинал».** Репро из обычной игры: мердж Cheetah A → Cheetah B (одинаковый тип тоже накапливает атрибут в `AccumulatedVisualAttributes`), затем B → C. `MergeView.OnMerge` применяет к C оба атрибута `[attrB, attrA]` в одном кадре: второй захватывает `[M0, glowB]` как свои «оригиналы», его финальный `Compose` записывает в рендерер уничтоженный материал → `[cheetah, null]` навсегда, `Undo` тоже восстанавливает null, третий мердж распространяет его дальше. Исправлено `CaptureOriginalMaterials(Renderer)`, отфильтровывающим любую запись, чей шейдер == `_glowMaterial.shader`. Побочный бонус: одновременное двойное аддитивное свечение исчезло само, без флага подавления. **Правило: любой рантайм-оверлей в слоте материала должен отфильтровываться при захвате исходного состояния.**
- **[WARNING, исправлено] `OnDestroy` должен доигрывать, а не просто отменять** — зовёт `FinishRunningSequenceImmediately()`, чтобы уничтожение владельца в середине свипа оставило цель со скином гепарда и без висящего overlay-слота, а не потеряло визуальный атрибут молча.
- **Undo в середине последовательности** синхронен и авторитетен: отмена CTS → destroy инстанса glow → дословное восстановление сохранённых `sharedMaterials`. Сознательно БЕЗ флага «я уже свопнул» — переприсваивание сохранённого массива корректно во всех трёх точках (до свопа, между проходами, после завершения). Undo достижим из `UndoMergeButton` и `KeyboardMergeUndoHelper` в пре-батле.
- **Zenject не задействован** — ни биндингов, ни установщиков, ни сигналов, только сериализованные ссылки; `new MergeSweepGlow(...)` создаётся владельцем. Тот же прецедент, что `DeathSpiritSpawner`/`DeathSpiritView` и решение по iridescent sweep от 2026-07-31.
- **Тайминги живут на `[SerializeField]` компонента, не в ScriptableObject** — авторские значения одного эффекта с единственным потребителем, а не геймплейный баланс. Триггер миграции: как только второй merge attribute (например `ElephantMergeAttribute`) захочет тот же свип — вынести `MergeSweepGlowConfig : ScriptableObject`.

### Известное ограничение (принято, не баг)
Когда длина массива материалов рендерера больше его `subMeshCount`, Unity перерисовывает лишним (glow) материалом только **последний** сабмеш. На многосабмешевых мешах свип покроет этот сабмеш, а не весь рендерер.

### Decisions
Полностью → [[2026-08-01-tutorial-hand-merge-hint]]. Кратко:
- **Расширяемость через `ITutorialStep`**: новый шаг = один класс + одна строка биндинга, `TutorialRunner` не трогается. `RunAsync` сам ждёт свой триггер внутри и возвращает `bool` — засчитывать шаг или нет.
- **Старт по `PreBattlePhaseStartedSignal` с `IsLevelStart == true`, а не в `Initialize()`.** Zenject зовёт `IInitializable.Initialize` из `MonoKernel.Start`, когда `GameBootstrapper.Awake` только вошёл в `BootstrapState` — `PlayerProgress` там может быть ещё `null`. К моменту сигнала прогресс загружен (`LoadProgressState` → `LoadLevelState` → `BattleLoopState` → `PreBattleState`).
- **Пара — по индексу спавна, не по координатам сетки.** `IUnitTracker._playerUnits` — обычный `List` в порядке регистрации = порядке спавна, `GetAlivePlayerUnits()` порядок сохраняет. Сетка отвергнута: `GridManager.PlaceOnGrid` берёт первую свободную клетку рядов y=0..1, позиция зависит от `UnitSize` ранее поставленных юнитов (Elephant 2×2 vs Cheetah 1×2) и от `GridConfig`. Стратегия `IMergeHintTargetResolver` с полем `Mode`, обе реализации биндятся, шаг берёт совпавшую с конфигом.
- **Новый `AllyMergedSignal` вместо подписки на события `MergeTarget`.** `MergeTarget.Merged` гейтится флагом `grantedNewSkill` (только cross-type), а подписка на `Merge` конкретных инстансов заставила бы туториал знать про Presentation-компонент и не засчитала бы мердж другой пары.
- **Отдельный `ITutorialProgressService` на PlayerPrefs**, а не поле в `PlayerProgress`: `Framework/` — стабильная база, поле в сериализуемом JSON затронуло бы `SaveLoadService`, `WinState`, `LoseState`.
- **Резолв пары — событийный, не пофреймовый**: `GetAlivePlayerUnits()` это `Where(...).ToList()`, поллинг каждый кадр всё пре-батл окно = мусор на мобиле. Используется `UniTaskCompletionSource<MergeHintPair>` поверх `IUnitTracker.PlayerUnitsChanged` + немедленная первая попытка.
- **Ввод не блокируется**: `raycastTarget = false`, `blocksRaycasts = false`, затемняющего оверлея нет — подсказка требует, чтобы игрок сам сделал мердж.
- **Мир→экран с камерой `null`**: Canvas из `Assets/Resources/Canvas.prefab` — Screen Space Overlay, поэтому `null` в `RectTransformUtility.ScreenPointToLocalPointInRectangle` корректен (прецедент `MergePopupController`).

### Ловушки для будущих сессий
- ⚠️ **UniTask DOTween-адаптер (`ToUniTask`) в этом проекте НЕДОСТУПЕН.** `UniTask.DOTween.asmdef` гейтит всё за `UNITASK_DOTWEEN_SUPPORT`, а `versionDefines` эмитит define только для UPM-пакета `com.demigiant.dotween`; здесь DOTween из Asset Store (`Assets/Plugins/Demigiant/DOTween/DOTween.dll`) → `DOTweenAsyncExtensions` не компилируется (проверено `unity_reflect`: 0 типов). `AsyncWaitForCompletion().AsUniTask()` не годится — Task-based, игнорирует токен, ломается при выходе из PlayMode. Рабочий приём: `UniTask.WaitUntil(() => !seq.IsActive() || seq.IsComplete(), cancellationToken: token).SuppressCancellationThrow()`. Включить нативный адаптер = добавить `UNITASK_DOTWEEN_SUPPORT` в `scriptingDefineSymbols` для Android/Standalone/iPhone — не делали.
- ⚠️ **Отписка от `SignalBus` должна быть синхронной относительно teardown контейнера.** `UniTask.WaitUntil` poll-based и не возобновляется синхронно на `Cancel()` — к следующему тику PlayerLoop Zenject уже сделал `SignalBus.LateDispose()`, и `Unsubscribe` кинул бы (`throwIfMissing: true`). `CancellationTokenSource.Cancel()` выполняет регистрации синхронно, а `SignalBus` — `ILateDisposable` (сносится после всех `IDisposable`), поэтому `TutorialRunner.Dispose()` разматывает подписки до исчезновения шины. Отсюда `CancelAwareSignalSubscription<T>`.
