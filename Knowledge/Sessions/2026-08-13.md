## Decisions

Полностью — в [[2026-08-13-battle-scene-builder]]. Коротко:

1. **Засев `GridManager._cells` рефлексией — ключевой приём всего инструмента.**
   `EnsureGridInitialized()` (`GridManager.cs:84`) рано выходит при `!Application.isPlaying`, поэтому
   в Edit Mode `_cells == null`. Следствие, которое легко не заметить: `CanPlaceUnit` (`:303`)
   итерирует пустой список и возвращает `true` для ЛЮБОЙ позиции → `TryFindFreePlacement` (`:699`)
   всегда отдаёт `(0,0)` → все союзники молча схлопываются в один угол, без единой ошибки в консоли.
   После засева работают настоящие `TryFindFreePlacement`/`CanPlaceUnit`/`GetOccupiedCells`/
   `SetOccupied`/`HasCellFor`, и логика раскладки не дублируется. Рефлексия, а не `SerializedObject`:
   поле `private GridCell[,] _cells`, 2D-массив Unity не сериализует (`SerializedObject` использован
   для `_cellPrefab`). Всё изолировано в `GridManagerEditorAccess`, при переименовании поля — явный
   `Debug.LogError`. `Clear()` возвращает `_cells = null` — ровно pre-Awake состояние.
2. **`GridManager.Rebuild(w, h, cellSize)` в Edit Mode использовать нельзя**: `ClearCells()` зовёт
   `Object.Destroy` (в Edit Mode запрещено) и выставляет `_hasRuntimeOverride`.
3. **У заспавненных животных в Edit Mode безопасны только `Place(Vector3)` и `RotateToTarget(Vector3)`.**
   `AnimalMovement._unitOccupancy` присваивается в `Awake`, поэтому `SetCurrentNode`/`FillNodes`/
   `ClearNodes`/`SetNewNode` дают NRE. Отсюда `GridManager.PlaceOnGrid` непригоден целиком (внутри
   `SetCurrentNode`) — инлайнен как `TryFindFreePlacement` → `GetCell` → `Place` → `SetOccupied`.
   Поворот в рантайме ставит `AnimalMovement.Start()`, которого в Edit Mode нет, — зовём сами.
   `AnimalFacade.Movement`/`.Type` доступны без Awake, `AnimalFacade.Occupancy` — нет (присваивается
   в `Start`).
4. **Guard и от Play Mode, и от сохранения сцены.** Клетки на слое `PathNode`, союзники на `Animal`
   — ровно те два слоя, по которым райкастит `AnimalMovement.TryPlace` (`AnimalMovement.cs:225`):
   мёртвое превью сломало бы мердж и выбор животных. Плюс `BattleSceneBuildRoot` компилируется только
   под `#if UNITY_EDITOR` — сохранённая с превью сцена дала бы missing script в плеерном билде.
   Guard зовёт полноценный `Clear()` (чтобы откатился и `_cells`), а не просто удаляет объект.
5. **Тумблера «Build Grid» нет намеренно.** Был, оказался мёртвой опцией: `Build` всегда начинается
   с `Clear()`, обнуляющего `_cells`, а без сетки юнитов размещать негде. Убран, а не «починен».
6. **Расстановка воспроизводит рантайм как есть, включая известные расхождения.** Гейт `HasCellFor`
   по таблице `GridManager.GetFootprint` (Fox/Hedgehog там 1×2 при фактическом `_unitSize` 1×1),
   ветка `ChickenFlock` 2×2 на 4 курицы, порядок пула. Враги — паритет с
   `EnemySpawnService.SpawnEnemyAtPosition`: те же клетки, слой `Enemy` только на корне, имя с
   `_{index}`; `ApplyStats` не зовётся (нужен `AnimalDatabase`, к визуалу отношения не имеет).
7. Сцена намеренно не сохраняется, `EditorSceneManager.SaveScene` не вызывается.

Полезны сами по себе, вне этой фичи:

- `PreBattleConfig.asset._startingPool` = `[Cheetah, Fox, Elephant]` — **не совпадает с концепт-доком**
  (`[Elephant, Cheetah, Hedgehog]`).

  `_isBoss`), `_isBossStage`, `_stageNumber`. Ассеты: `Assets/Settings/LevelConfigs/LevelStageConfig_1..4.asset`.
  `LevelStageConfig_1` = 6× `EnemyChicken_Temp` в клетках (1..6, 9).
- `Assets/Resources/Levels/Level_1..4.prefab` содержат **только** `ExtendedLevel` с массивом
  `_stages` — ни сетки, ни геометрии.
- В `Main Scene.unity`: `GameGrid` в (0,0,0), конфиг 8×10, cellSize 1; `MergeGrid` в (0,0,−3),
  конфиг 8×2, cellSize 1. Оба Untagged.
- `_unitSize` в префабах союзников: Cheetah 1×2, Deer 1×2, Elephant 2×2, Chicken 1×1, Fox 1×1,
  Hedgehog 1×1. `_direction` у всех North, `_yPos` 0, `_zOffset` −0.5 у Deer и Elephant.
