## Decisions

1. **Зум = долли (сдвиг Transform вдоль forward), а НЕ анимация FOV.** У `Main Camera` есть
   дочерняя `HealthBarCamera` (clearFlags Depth only, culling mask = слой 8 HealthBar, свой FOV 60).
   Анимация `Camera.main.fieldOfView` рассинхронизировала бы все хелсбары с юнитами — дочерняя
   камера сохранила бы свой FOV. Долли двигает родительский Transform, дочерняя едет следом
   по построению. Если когда-нибудь понадобится FOV-режим — гнать FOV по всем
   `GetComponentsInChildren<Camera>()`.
2. **Триггер — не клик по кнопке Fight.** `BattleReadinessService` может отклонить старт, и камера
   уехала бы впустую. Единственная точка «бой реально начался» — `PreBattleState.StartBattleAsync()`.
3. **Твин — UniTask-цикл с `AnimationCurve`, не DOTween.** `UNITASK_DOTWEEN_SUPPORT` в проекте
   не определён, `DOTWEEN_ASYNC` определён только для Android → await'абельный DOTween-твин
   непортируем на iOS. Образец — `Assets/Code/Animals/Vfx/MergeScaleTween.cs`.
4. **Namespace `Code.Battle.CameraControl`, а не `Code.Battle.Camera`** — во втором случае
   идентификатор `Camera` резолвится в namespace, а не в `UnityEngine.Camera` → CS0118.
5. **Каждый твин стартует от ТЕКУЩЕЙ позиции камеры** (не от номинальной базы/цели) + внутренний
   CTS отменяет предыдущий. Прерывание зум-ина зум-аутом даёт плавный переход, а не скачок;
   повторный зум-аут идемпотентен (base → base, завершается за кадр).
6. **Диапазон `Range(0, 4.5)` для `_dollyDistance` выведен из авторской позы камеры в сцене**
   (pos `(3.06, 16.09, −8.76)`, pitch 45°, FOV 60): при d ≈ 4.73 из кадра уходит задний ряд зоны
   деплоя (z = −2.5). ⚠️ Если камеру в сцене подвинут — диапазон надо пересчитать.

## Decisions

1. 🔴 **`AnimalStatsPanelView` — screen-space, а НЕ world-space.** Живёт в единственном
   экземпляре в корне overlay-`Canvas` и проецирует мировую позицию юнита через
   `Camera.WorldToScreenPoint` в `LateUpdate`. Визуально выглядит как world-space — отсюда
   частое заблуждение. **Единственный настоящий world-space UI** в префабах животных —
   `HealthBar.prefab` (слой `HealthBar` 8, рисуется отдельной `HealthBarCamera`).
2. 🔴 **Врага нельзя выбрать тапом.** `AnimalMover.CastRay()` кастует
   `LayerMask.GetMask("Animal")`, враги на слое `Enemy` (23). Карточка врага физически не
   могла ехать через `IAnimalSelectionService` — отсюда свой презентер от `IUnitTracker`.
   Расширять маску райкаста не стали: тап по врагу — часть игрового ввода.
3. 🔴 **TMP молча игнорирует `Graphic.material`.** `TextMeshProUGUI` наследует `Graphic`, но
   не роутит `Graphic.material` в свой рендер: присваивание проходит **без ошибки и без
   эффекта**. Материальные эффекты на TMP — только через `TMP_Text.fontMaterial`.
4. **Серый спрайт FIGHT решено не рисовать.** `ColorTint` поверх оранжевого даёт коричневый;
   grayscale-материал поверх того же спрайта даёт честный металлик и не плодит парный ассет.
5. **Карточка врага показывается один раз за бой и перенацеливается**, а не прячется на
   каждом ходу игрока — иначе на каждом показе пересоздаётся DOTween-сиквенс появления, и
   карточка мигала бы N раз за раунд.
6. **Сторона юнита — только через трекер** (`IUnitTracker.GetAliveEnemyUnits()`). Продолжение
   решения 2026-08-02: temp-враги наследуются от `PlayerAnimalFacade`, `unit is
   EnemyAnimalFacade` врёт.
7. **`IAbility` не расширяем на этой итерации** ради реальных процентов — расширение задевает
   все способности и подклассы `AnimalStats`. Вместо этого трёхзначный `abilityLines`, который
   не потребует смены сигнатуры, когда данные появятся.
