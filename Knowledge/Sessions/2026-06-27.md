## Фича: Подсветка радиуса хода

### Done
- Реализована подсветка доступных ходов животного при удержании клика/тапа: при нажатии и удержании (~0.15с без движения) на животном подсвечиваются клетки сетки, достижимые в пределах его `TilesPerMove`. При начале драга (смещение за порог) подсветка убирается и работает обычный drag-n-drop размещения.
- НОВЫЙ `Assets/Code/Animals/Movement/MoveRangeHighlighter.cs` + `IMoveRangeHighlighter.cs` — отдельная сущность, инкапсулирует BFS-расчёт достижимых клеток (8-направленный flood-fill глубиной `TilesPerMove`, через `IGridManager.CanPlaceUnit(..., excludeFootprint)` + проверку `GetCell != null`) и саму подсветку. Plain C#-класс, биндится в Zenject `AsSingle`.
- `Assets/Code/GridPathfinding/GridCell.cs` — добавлен сериализуемый `_moveRangeColor` (настраивается в Inspector) + метод `HighlightMoveRange(bool)`.
- `Assets/Code/Animals/AnimalMover.cs` — `Update` переписан в gesture-машину удержание/драг (OnPress → OnHeld → BeginDrag → OnRelease + ResetGesture); добавлен инжект `IMoveRangeHighlighter`, поля `_dragThresholdPixels`/`_holdTimeToShow`; `SaveState()/ClearNodes()` перенесены из `TryPickAnimal` в `BeginDrag` (удержание без драга больше не трогает occupancy).
- `Assets/Code/Infrastructure/Installers/CurrentGameInstaller.cs` — биндинг `IMoveRangeHighlighter → MoveRangeHighlighter AsSingle`.

### Decisions
- Новая логика вынесена в отдельную сущность (SRP) — НЕ нагружали `AnimalMovement`, который уже отвечает за движение/dodge/retreat/occupancy/поворот. `AnimalMovement` не менялся, из него только читаются public-данные (`CurrentPathNode`, `UnitSize`, `Direction`, `TilesPerMove`).
- Подсветка = радиус хода по ВСЕЙ сетке (без ограничения зоной деплоя Y<=1), т.к. это превью боевого перемещения, а не зона размещения.
- Drag vs hold различается порогом смещения в пикселях (с поправкой на DPI), а не изменением `IInputService` — интерфейс не трогали.
- BFS повторяет двойную проверку pathfinder'а (`CanPlaceUnit` + `GetCell != null`) из-за молчаливого клампа `AdjustPositionToFitBounds` в `GridManager`.

### Done

- НОВЫЙ `Assets/Code/Animals/UI/MergePopupView.cs` — точная копия анимации `DamagePopupView` (`Play(string, Color)` → DOTween float-up + fade → Destroy). Namespace `Code.Animals.UI`.
- НОВЫЙ `Assets/Code/Animals/UI/MergePopupController.cs` — зеркало `DamagePopupController`. `[Inject] Construct(AnimalDatabase)` (переиспользует существующий биндинг). Подписка/отписка на `MergeTarget.Merged` в OnEnable/OnDisable; `OnMerged(source)` берёт строку через `GetMergeInfo(source.Type)`, спавнит popup над выжившим target цветом `GainColor` (зелёный); при пустой строке — не показывает.
- `Assets/Code/Animals/Merge/MergeTarget.cs` — добавлено событие `public event Action<PlayerAnimalFacade> Merged` (рядом с существующим `Merge` для MergeView — его не трогали). Фаерится в `ExecuteMergeDirectly`, передаёт ПОТРЕБЛЁННОЕ (source) животное; гейтится флагом `grantedNewSkill`.
- `Assets/Code/Data/Animals/AnimalDatabase.cs` — в `AnimalConfig` добавлено `[TextArea] string MergeInfo`; в `AnimalDatabase` добавлен `string GetMergeInfo(AnimalType)` (зеркало `GetStats`, возвращает `string.Empty` + warning если тип не найден). `GetStats` не тронут.

### Decisions
- Popup ключуется по типу SOURCE (потреблённого) животного — именно его `MergeSkill` применяется к target.
- Событие `Merged` фаерится ТОЛЬКО на cross-type ветке `ExecuteMergeDirectly` (флаг `grantedNewSkill`). Same-type мердж (только комбинируются HP/damage, нового скилла нет) popup НЕ показывает, чтобы не дезинформировать игрока. Гарантии: ровно один раз на квалифицирующий мердж, никогда на failed/rejected, никогда на undo (undo идёт через `MergeCommand`/`IMergeUndoService`, минуя `ExecuteMergeDirectly`).
- Переиспользован существующий per-prefab controller pattern и overlay-canvas как у `DamagePopupController`; новых installer/сервисов не вводилось.
