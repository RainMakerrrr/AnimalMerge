# Решение: смерть курицы — доразводка существующих стейтов + дух как запечённая копия её же меша

**Дата:** 2026-07-31
**Статус:** принято, реализовано

## Контекст

Задача звучала как «у курицы нет анимации смерти, надо сделать вылет духа-призрака». При разборе выяснилось, что это две независимые проблемы, и первая — не «сделать», а «доделать».

В `Assets/Animals3D/Animators/Chicken/ChickentwoLayerController.controller`:
- Параметр `IsDead` существовал, но его **единственный** переход шёл `idle --IsDead--> jump`. Курица при смерти **подпрыгивала** — и только если умирала из `idle`; при смерти во время `move`/`peck`/`honk`/`flapping` не происходило вообще ничего.
- При этом в контроллере лежали **два готовых неиспользуемых стейта смерти**: `down` (клип `down.anim`, 1.333 с, non-looping, тег `Stop`) на Base Layer и `wing_down` на маскированном Wing Layer. В них не вёл ни один переход.
- Исходящий переход из `down` был завязан на несуществующий параметр `jump` (со строчной буквы) — мёртвый, но сыпал варнингом.

То есть автор анимаций сделал позу смерти для обоих слоёв, а разводку не доделали. Новый арт для падения не требовался.

Вторая часть: VFX-инфраструктуры в проекте нет вообще — ноль `ParticleSystem` в `Assets/Code/`, ни одного эффект-префаба, ни пула эффектов.

## Рассмотренные варианты для духа

1. **Запечённая копия меша самой курицы** (выбрано) — `SkinnedMeshRenderer.BakeMesh()` снимает позу в момент смерти, копия с эфирным материалом улетает вверх.
2. **Стилизованный мультяшный призрак** — отдельный спрайт/меш. Мгновенно читается как «призрак», дешевле по draw calls, но требует нового арта и не связан с видом животного.
3. **Только партиклы** — вихрь искр вверх. Минимум работы, но читается как «пыль», а не как душа; плюс в проекте нет ни одной ParticleSystem, то есть инфраструктуру всё равно пришлось бы заводить.

## Принятое решение

### Часть 1 — доразводка аниматора

Правки сделаны через `UnityEditor.Animations.AnimatorController` API (не ручным редактированием YAML — там связанные fileID):
- удалён `idle --IsDead--> jump`;
- удалён мёртвый `down --[jump]--> recovery`;
- добавлен `Any State --IsDead--> down` (Base Layer) и `Any State --IsDead--> wing_down` (Wing Layer);
- `IsDead` сменён с Trigger на **Bool**.

Диф контроллера — ровно эти пять правок, 55/55 строк, без переразметки.

### Часть 2 — эффект духа

Новая папка `Assets/Code/Animals/Vfx/`, ноль Zenject-поверхности (только сериализованные ссылки, по образцу `DamagePopupController`):
- `DeathSpiritSpawner` — на корне `Chicken.prefab`. Подписка на `AnimalHealth.Died` в `OnEnable`/`OnDisable`, `UniTask.Delay(0.35 с)` с `CancellationTokenSource`, `BakeMesh(mesh, useScale: true)`, `Instantiate` духа.
- `DeathSpiritView` — на `Assets/Prefabs/DeathSpiritView.prefab`. DOTween-секвенция 1.8 с: подъём 2.5 юнита, scale ×1.4, yaw +40°, покачивание по X ±0.25 (Yoyo), затухание на последних 45 %.
- Материал `Assets/Code/Animals/Materials/GhostSpirit.mat` на существующем `Voodoo_LaunchOps/FX/IridescentSweep` (см. [[2026-07-31-iridescent-sweep-shader]]).

## Почему так

- **Дух = копия меша, а не отдельный арт.** Ноль новых ассетов, силуэт узнаётся как «душа именно курицы», и механизм бесплатно переносится на любое животное — а он ещё понадобится: у `Deer` `IsDead` не ведёт никуда, у `Fox` ведёт в `Fox_Stun`, то есть у них смерти тоже нет.

- **`Any State`, а не переход из конкретного стейта.** Исходная разводка ловила смерть только из `idle` — это и была причина, по которой «анимации смерти нет» в большинстве случаев. `Any State` закрывает все стейты одним переходом.

- **`IsDead` сделан Bool, а не оставлен Trigger.** `AnimalAnimator.DeathAnimation()` (`Assets/Code/Animals/AnimalAnimator.cs:56`) вызывает `SetBool` — с Trigger это работало по совпадению (триггеры внутри хранятся как bool). С Bool поза смерти залипает навсегда и переход остаётся валидным при любой переоценке.

- **`canTransitionToSelf = false` — обязательно, а не для красоты.** Bool-параметр остаётся `true` вечно; при `canTransitionToSelf = true` переход `Any State → down` перезапускался бы каждый кадр, и анимация замерла бы на первом кадре. Это прямое следствие предыдущего пункта.

- **Переход смерти поставлен ИНДЕКСОМ 0**, раньше существовавшего `Any State --TakeDamage--> damage`. `AnimalHealth.TakeDamageAsync` (строки 142–147) вызывает `TakeDamageAnimation()` **прямо перед** `Die()`, поэтому на добивающем ударе оба перехода конкурируют в одном кадре. Порядок в `anyStateTransitions` — это и есть приоритет. Проверено эмпирически: в `damage` анимация не заходит вообще.

- **Дух спавнится БЕЗ РОДИТЕЛЯ.** `AnimalHealth.Die()` уничтожает тело через 3 с (`DestroyWithDelay`); ребёнок умер бы вместе с ним на середине полёта. Тот же приём, что у `DamagePopupView`, который живёт на канвасе, а не на животном.

- **Задержка 0.35 с перед вылетом** — чтобы тело успело начать падать и дух читался как отделяющийся от него, а не как выпрыгивающий из живой курицы.

- **Затухание через множитель на весах свечения, а не через альфу.** Шейдер аддитивный (`Blend One One`) — альфа в нём не участвует. Гасится общий множитель `1 → 0`, применяемый к `_RimWeight`, `_SurfaceWeight`, `_RimStrength`, `_SweepIntensity`.

- **`_SweepAxisExtent` выставляется в рантайме** из `bounds.size.y` запечённого меша. Это снимает то самое ограничение, которое в решении по шейдеру записано как «цена отказа от C#»: переиспользование на другом животном больше не требует ручной настройки под размах меша.

- **Пул не делался, хотя `AgentsDocs/UnityPatterns.md` требует пул для VFX.** В пошаговом баттлере смертей единицы за бой, а запечённый меш всё равно уникален на каждый вызов, поэтому переиспользовать объект почти нечего. Пошли по прецеденту `DamagePopupView` (`Instantiate`/`Destroy`). Замерено: 10 смертей подряд дают дельту 0 по мешам и 0 по материалам.

## Ловушка, которую надо помнить

`SkinnedMeshRenderer.BakeMesh()` создаёт `new Mesh()`, а обращение к `Renderer.material` создаёт инстанс материала — **ни то, ни другое не собирается GC**. Без `Destroy(_mesh)` и `Destroy(_material)` в `OnDestroy` каждая смерть навсегда оставляла бы в памяти ~1400-вершинный меш и материал. Это единственная реальная опасность в эффекте, и её проверка вынесена в отдельный замер.

## Проверка

- 0 ошибок компиляции. Варнинг про параметр `jump` пропал; остались 4 предсуществующих варнинга ассет-пака (`peck`, `to_flapping` ×2, `to_landing`) в стейтах, которых задача не касалась.
- В приватной preview-сцене (открытая сцена не трогалась): после `IsDead = true` обе прослойки уходят в `down` / `wing_down`; в `jump` и `damage` не заходит.
- **`down.anim` — реальное падение, а не присед**, измерено запеканием вершин: центроид Y 0.3018 → 0.1752 (−42 %), верхняя точка 0.7335 → 0.5282, высота 0.7328 → 0.5471.
- Гонка `damage` vs `down` на добивающем ударе: воспроизведён точный порядок вызовов `AnimalHealth` — выигрывает смерть.
- Кривая полёта проскраблена через `Sequence.Goto` (детерминированно, без ожидания wall-clock): y 0 → 2.495, x 0 → 0.25 → 0.002, scale 1 → 1.4, yaw 0 → 39.9°, свечение держится до t = 0.99 и затем гаснет (rim 2.2 → 0.263).
- Утечки: 10 куриц убиты полным реальным циклом (`Die()` через рефлексию) — все тела и духи удалились, дельта мешей **0**, дельта материалов **0**.
- EditMode: 634 теста, падения только предсуществующие (16 `TargetPositionCalculator`, 9 `AnimalAttackPostAbility`/`Retreat`) — регрессий нет. Новые тесты не писались — **TESTS PAUSED**.

**НЕ проверено:** визуальный вид на экране. Механика верифицирована данными, но подбор оттенка и интенсивности требует глаз. Шейдер аддитивный — только осветляет, никогда не затемняет, поэтому на светлом фоне дух может выцвести; тюнинг — `_RimWeight` вверх, `_SurfaceWeight` вниз.

## Доработка: аддитив заменён на альфа-блендинг (отдельный шейдер)

Первая версия материала духа стояла на `Voodoo_LaunchOps/FX/IridescentSweep` — аддитивном (`Blend One One`). Офскрин-рендер реального меша показал предел этого подхода наглядно: на тёмном фоне светятся только края, а внутренность тела остаётся почти чёрной; на светлом фоне дух выцветает в白 белое пятно и теряет весь цвет. Аддитив умеет только **прибавлять** свет, поэтому ни «наполненности цветом», ни управления прозрачностью у него нет в принципе — это не вопрос настройки.

Решение: **новый отдельный шейдер** `Assets/Shaders/SpiritGhost.shader` (`Voodoo_LaunchOps/FX/SpiritGhost`), `Blend SrcAlpha OneMinusSrcAlpha`, `ZWrite Off`, `Queue Transparent`. Та же математика волны и Fresnel, но:
- `_BaseColor` заливает тело, `_RimColor` подсвечивает силуэт, между ними `lerp` по Fresnel;
- `_Alpha` (0..1) — прямое управление прозрачностью, чего у аддитива не было; итоговая альфа = `_Alpha + fresnel * _RimAlphaBoost + band * ...`, поэтому края плотнее центра (классический призрак);
- `_Fade` (0..1) — **один** параметр затухания, гасит альфу целиком.

`IridescentSweep.shader` намеренно **не трогался**: он общий с эффектом loot shine на `Cheetah.prefab`, и смена blend-режима сломала бы его; плюс файл в этот момент правила параллельная сессия.

Побочно упростился C#: `DeathSpiritView` раньше тюнил четыре веса свечения (`_SurfaceWeight`, `_RimWeight`, `_RimStrength`, `_SweepIntensity`) через общий множитель, теперь тянет один `_Fade`. Минус ~20 строк, `CaptureBaseGlow()` удалён.

Проверено рендером: на светлом фоне дух стал насыщенно-голубым силуэтом вместо белого пятна, на тёмном — заливка тела читается, края светятся. Вид консистентен между фонами — главный выигрыш альфа-блендинга. Дефолт `_Alpha = 0.75`; 0.55 заметно прозрачнее, 0.92 почти непрозрачно и слегка теряет призрачность.

## Ловушка инструментария: окно Animator откатывает правки через API

Через полчаса после успешной правки контроллер на диске оказался **частично откатан**: смена `IsDead` на Bool уцелела, а оба добавленных `Any State`-перехода исчезли и оба удалённых вернулись (диф схлопнулся до одной строки). Причина — открытое окно Animator: оно держит граф контроллера в памяти со своим состоянием и сбрасывает его на диск, затирая правки, сделанные через `UnityEditor.Animations` API. Косвенный признак, что окно открыто, — предсуществующий NRE `UnityEditor.Graphs.Edge.WakeUp` в консоли.

Коварство в том, что откат частичный и отложенный: проверка сразу после правки проходит, а замеры поведения спустя время начинают противоречить друг другу, и это выглядит как ошибка в собственной логике.

Правило: перед правкой контроллера через API закрывать окно Animator, а результат проверять `git diff` по файлу, а не только перечитыванием ассета из памяти.

```csharp
var t = System.Type.GetType("UnityEditor.Graphs.AnimatorControllerTool, UnityEditor.Graphs");
foreach (var w in UnityEngine.Resources.FindObjectsOfTypeAll(t))
    ((UnityEditor.EditorWindow)w).Close();
```

## Затронутые файлы

Новые: `Assets/Shaders/SpiritGhost.shader` (+`.meta`), `Assets/Code/Animals/Vfx/DeathSpiritView.cs`, `Assets/Code/Animals/Vfx/DeathSpiritSpawner.cs` (+`.meta`), `Assets/Code/Animals/Materials/GhostSpirit.mat` (+`.meta`), `Assets/Prefabs/DeathSpiritView.prefab` (+`.meta`).
Изменены: `Assets/Animals3D/Animators/Chicken/ChickentwoLayerController.controller`, `Assets/Resources/Prefabs/Animals/Chicken.prefab` (+18 строк), `Assets/Resources/Prefabs/Enemies/EnemyChicken_Temp.prefab` (+18 строк).
C# существующих систем **не трогался** — `AnimalHealth`, `AnimalAnimator`, инсталлеры и сигналы без изменений.

**Вражеская курица** (`EnemyChicken_Temp.prefab`) делит с союзной тот же `ChickentwoLayerController`, поэтому разводку аниматора унаследовала автоматически — потребовалось только повесить `DeathSpiritSpawner` и заполнить три ссылки (`_health`, `Chicken_body`, `DeathSpiritView.prefab`). Меш и габариты идентичны (1389 вершин, bounds 0.73), поведение замерено отдельно и совпадает: `down` за 0.10 с, обе прослойки в позе смерти, центроид 0.3018 → 0.1748, 10 смертей подряд → дельта мешей 0 и ноль материалов вида `GhostSpirit (Instance)`.

`DeathSpiritSpawner.OnDied()` помечен `[ContextMenu("OnDead")]` (добавлено пользователем для ручного превью эффекта из инспектора) и создаёт `CancellationTokenSource` лениво — иначе вызов из контекстного меню при незаполненном `_health` падал бы в NRE, потому что `OnEnable` выходит раньше создания CTS.
