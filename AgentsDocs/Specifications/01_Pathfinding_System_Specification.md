**Дата:** 2026-01-25
**Статус:** В разработке

## 1. Обзор

Система поиска пути (Pathfinding System) отвечает за расчет маршрутов передвижения игровых юнитов (животных и врагов) по тактическому полю боя с учетом:
- Габаритов юнита (1x1, 1x2, 2x2 клетки)
- Препятствий и занятых клеток
- Специальных типов передвижения (ходьба, полет, прыжки)
- Ограничения дальности хода

**Фокус первого этапа:** Базовое передвижение (walking) для всех юнитов. Специальные типы движения будут реализованы позже.

## 2. Геймплейные требования из концепт-дока

### 2.1 Игровое поле
- **Поле боя:** 8×10 клеток (ширина × высота)
- **Зона выкладки игрока:** первые 2 строки снизу (2×8 клеток)
- **Зона врагов:** верхние строки

### 2.4 Правила передвижения

#### 2.4.1 Общие правила
- **Направления:** только 4 стороны (вверх, вниз, влево, вправо), **диагонали запрещены**
- **Очередность ходов:**
  - Первыми ходят юниты игрока (слева-направо, сверху-вниз)
  - Затем враги (слева-направо, снизу-вверх)
- **Атака:** можно атаковать по диагонали ("достаем")
- **Блокировка:** юниты блокируют клетки, нельзя пройти сквозь них

#### 2.4.2 Специальные типы передвижения

> **Примечание:** Эти механики будут реализованы на втором этапе. Сначала фокус на базовом передвижении.

**Полет (Орёл, Птеродактиль, Дракон):**
- Игнорируют других юнитов на пути
- Могут "перелететь" через препятствия
- Не могут приземлиться на занятую клетку
- Скорость: х0.3 в полёте (?)

**Додж (Лиса):**
- При попытке атаки уклоняется на клетку в сторону
- Приоритет уклонения: в сторону → назад → куда угодно свободно
- Если некуда уклониться - прыгает на месте, но всё равно доджит
- Первый раз срабатывает 100%, потом 80% у владельца, 50% у унаследовавшего
- **Не работает против AoE атаки и атаки с воздуха**

**Прыжок (Кенгуру):**
- Может перепрыгивать через препятствия
- Даёт прыжок + ×0.2 к ходу при мердже

**Отбегание (Велоцирапторы):**
- После атаки отбегают на 1-4 клетки назад
- Если не атаковали - остаются на месте

#### 4.2.1 Основные возможности

1. **Поиск пути с учетом габаритов:**
   - Юнит размером 2×2 не должен пытаться пройти через проход 1 клетка
   - Anchor point юнита (точка отсчета) = левый нижний угол

2. **Типы передвижения:**
   - `Walking` - обычная ходьба (блокируется другими юнитами)
   - `Flying` - полет (игнорирует юнитов на пути, но не может приземлиться на занятую клетку)
   - `Jumping` - прыжок (может перепрыгивать через препятствия)
   - `Teleport` - телепортация (мгновенное перемещение, для скиллов)

3. **Ограничение дальности:**
   - Учет максимальной дальности хода юнита
   - Возможность получить все доступные клетки в радиусе хода

4. **Направление юнита:**
   - Поворот юнита влияет на занимаемые клетки (для несимметричных юнитов 1×2)
   - 4 направления: North, East, South, West

5. **Проверка возможности размещения:**
   - Можно ли разместить юнита размером NxM на позиции (x, y)?
   - Учет поворота

6. **Визуализация (опционально):**
   - Подсветка доступных для хода клеток
   - Визуализация найденного пути
   - Цветовое кодирование (свободно/занято/недоступно)

#### 4.2.2 Дополнительные возможности

7. **Поиск ближайшей свободной клетки:**
   - Если целевая клетка занята, найти ближайшую свободную

8. **Группировка юнитов (для куриц-боссов):**
   - "Облепление" ближайшего врага со всех сторон

9. **Кеширование путей:**
   - Для оптимизации, если несколько юнитов идут в одну точку

### 4.3 Производительность

**Целевые метрики:**
- Поиск пути для одного юнита: **< 5 мс**
- Расчет всех доступных клеток: **< 10 мс**
- Без аллокаций в куче (Object pooling)
- Поддержка до **20 юнитов** одновременно на поле

## 6. Алгоритмы

### 6.1 A* Pathfinding

**Алгоритм:** A* (A-star) с Manhattan distance heuristic

**Основные шаги:**
1. Инициализация:
   - Open list (приоритетная очередь по FCost)
   - Closed set (уже обработанные узлы)

2. Главный цикл:
   - Взять узел с минимальным FCost из Open list
   - Если это целевой узел → путь найден
   - Добавить в Closed set
   - Для каждого соседа:
     - Пропустить, если в Closed set
     - **Проверить, может ли юнит занять эту клетку с учетом размера**
     - Рассчитать новый GCost
     - Если лучше текущего → обновить и добавить в Open list

3. Эвристика (HCost):
   ```
   H = |targetX - currentX| + |targetY - currentY|
   ```

4. Финальная стоимость:
   ```
   FCost = GCost + HCost
   ```

### 6.2 Проверка размещения (CanPlaceUnit)

**Алгоритм:**
```
Для каждой клетки, которую займет юнит:
    Рассчитать координаты с учетом направления
    Проверить:
        - В границах сетки?
        - Проходима? (IsWalkable)
        - Свободна? (не занята другим юнитом)
    Если хоть одна не подходит → return false
return true
```

**Пример для юнита 1×2 (олень):**
- Direction = North: занимает клетки (x, y) и (x, y+1)
- Direction = East: занимает клетки (x, y) и (x+1, y)

### 6.3 Получение доступных клеток (GetReachableCells)

**Алгоритм:** BFS (Breadth-First Search) с ограничением по расстоянию

```
queue = [startPosition]
visited = {startPosition}
result = []

while queue not empty:
    current = queue.pop()
    distance = CalculateDistance(start, current)

    if distance > maxDistance:
        continue

    if CanPlaceUnit(current, unitSize, direction):
        result.add(current)

    for neighbor in GetNeighbors(current):
        if neighbor not in visited:
            visited.add(neighbor)
            queue.add(neighbor)

return result
```

### 6.4 Поиск позиций для атаки (GetPossibleMoves)

**Проблема:** Необходимо найти все валидные позиции (anchor points), с которых юнит может атаковать цель.

**Ключевое отличие от старого подхода:**
- ❌ **Неправильно:** Брать соседние клетки от цели и использовать их как anchor points
- ✅ **Правильно:** Построить зону атаки вокруг ВСЕХ клеток цели, затем для каждой клетки зоны найти возможные anchor points, при которых юнит займет эту клетку

#### 6.4.1 Термины

**Anchor Point** — опорная точка юнита, левый нижний угол занимаемой области. От anchor point отсчитываются все остальные клетки юнита согласно его размеру и направлению.

**Зона атаки** — множество клеток, с которых можно атаковать цель (все соседи клеток цели по расстоянию Чебышева ≤ 1, включая диагонали).

**Обратное преобразование** — процесс нахождения всех возможных anchor points, при которых юнит займет конкретную клетку.

#### 6.4.2 Алгоритм GetPossibleMoves

**Входные данные:**
- `target` — позиция цели в мировых координатах
- `CurrentTarget.Transformable` — информация о цели (anchor point, размер)
- `_sizeType` — размер атакующего юнита
- `_direction` — направление атакующего юнита
- `_currentPathNode` — текущая позиция атакующего юнита

**Шаги алгоритма:**

```
1. Получить все клетки цели
   targetCells = GetAllTargetCells(targetTransformable)

   Если цели нет или клеток нет:
       return простой список 8 соседей вокруг target (fallback)

2. Построить зону атаки
   attackZone = {}
   Для каждой клетки цели:
       Добавить всех соседей (8 направлений, расстояние Чебышева ≤ 1)

3. Вычислить кандидатов anchor points
   candidateAnchors = {}
   unitSize = _sizeType.ToUnitSize()
   unitDirection = _direction.ToDirection()

   Для каждой клетки из attackZone:
       anchors = GetAnchorPointsForCell(attackCell, unitSize, unitDirection)
       Добавить все anchors в candidateAnchors

4. Фильтрация
   validPositions = []
   Для каждого anchor из candidateAnchors:
       Если _gridManager.CanPlaceUnit(anchor, unitSize, unitDirection, ignoreOccupied: true):
           Добавить anchor в validPositions

   Параметр ignoreOccupied: true нужен, чтобы игнорировать
   текущую позицию самого атакующего юнита

5. Приоритизация
   Сортировать validPositions по:
       Первичный критерий: минимальное |deltaX| от текущей позиции
       Вторичный критерий: предпочитать большие deltaY (движение вперед)

   return validPositions.ToArray()
```

#### 6.4.3 Вспомогательный метод GetAllTargetCells

**Назначение:** Получить список всех клеток, занимаемых целью.

**Алгоритм:**
```csharp
private List<GridCell> GetAllTargetCells(ITransformable targetTransformable)
{
    List<GridCell> targetCells = new List<GridCell>();

    // Добавляем anchor point цели
    if (targetTransformable.CurrentPathNode != null)
    {
        targetCells.Add(targetTransformable.CurrentPathNode);
    }

    // Добавляем дополнительные клетки (для юнитов >1×1)
    if (targetTransformable is AnimalMovement targetAnimal)
    {
        targetCells.AddRange(targetAnimal.Nodes);
    }

    return targetCells;
}
```

**Для юнита 2×2 на позиции (3,8):**
- CurrentPathNode = (3,8)
- Nodes = [(3,9), (4,8), (4,9)]
- Результат: [(3,8), (3,9), (4,8), (4,9)]

#### 6.4.4 Ключевой метод GetAnchorPointsForCell

**Назначение:** Для заданной клетки найти все возможные anchor points, при которых юнит займет эту клетку.

**Входные данные:**
- `targetCell` — клетка, которую должен занять юнит
- `unitSize` — размер юнита (Width × Height)
- `unitDirection` — направление юнита (North/East/South/West)

**Логика для разных размеров:**

##### Юнит 1×1 (Small)
Занимает только anchor point.
```
Если нужна клетка (x, y):
    anchor = (x, y)

Результат: 1 вариант
```

##### Юнит 1×2 (Medium) с Direction.North
Занимает: `(anchor.x, anchor.y)`, `(anchor.x, anchor.y+1)`
```
Если нужна клетка (x, y):
    Вариант 1: anchor = (x, y)     — клетка как первая (0,0)
    Вариант 2: anchor = (x, y-1)   — клетка как вторая (0,1)

Результат: 2 варианта
```

##### Юнит 1×2 с Direction.South
Занимает: `(anchor.x, anchor.y)`, `(anchor.x, anchor.y-1)`
```
Если нужна клетка (x, y):
    Вариант 1: anchor = (x, y)
    Вариант 2: anchor = (x, y+1)
```

##### Юнит 1×2 с Direction.East
Занимает: `(anchor.x, anchor.y)`, `(anchor.x+1, anchor.y)`
```
Если нужна клетка (x, y):
    Вариант 1: anchor = (x, y)
    Вариант 2: anchor = (x-1, y)
```

##### Юнит 1×2 с Direction.West
Занимает: `(anchor.x, anchor.y)`, `(anchor.x-1, anchor.y)`
```
Если нужна клетка (x, y):
    Вариант 1: anchor = (x, y)
    Вариант 2: anchor = (x+1, y)
```

##### Юнит 2×2 (Large) с Direction.North или East
Занимает: `(anchor.x, anchor.y)`, `(anchor.x+1, anchor.y)`, `(anchor.x, anchor.y+1)`, `(anchor.x+1, anchor.y+1)`
```
Если нужна клетка (x, y):
    Вариант 1: anchor = (x, y)       — offset (0,0)
    Вариант 2: anchor = (x-1, y)     — offset (1,0)
    Вариант 3: anchor = (x, y-1)     — offset (0,1)
    Вариант 4: anchor = (x-1, y-1)   — offset (1,1)

Результат: 4 варианта
```

##### Юнит 2×2 с Direction.South
Занимает: `(anchor.x, anchor.y)`, `(anchor.x+1, anchor.y)`, `(anchor.x, anchor.y-1)`, `(anchor.x+1, anchor.y-1)`
```
Если нужна клетка (x, y):
    Вариант 1: anchor = (x, y)
    Вариант 2: anchor = (x-1, y)
    Вариант 3: anchor = (x, y+1)
    Вариант 4: anchor = (x-1, y+1)
```

##### Юнит 2×2 с Direction.West
Занимает: `(anchor.x, anchor.y)`, `(anchor.x-1, anchor.y)`, `(anchor.x, anchor.y+1)`, `(anchor.x-1, anchor.y+1)`
```
Если нужна клетка (x, y):
    Вариант 1: anchor = (x, y)
    Вариант 2: anchor = (x+1, y)
    Вариант 3: anchor = (x, y-1)
    Вариант 4: anchor = (x+1, y-1)
```

#### 6.4.5 Пример работы алгоритма

**Исходная ситуация:**
- Атакующий слон 2×2 с Direction.North на anchor (3,0)
  - Занимает: (3,0), (4,0), (3,1), (4,1)
- Цель: вражеский слон 2×2 с Direction.North на anchor (3,8)
  - Занимает: (3,8), (4,8), (3,9), (4,9)

**Шаг 1: Клетки цели**
```
targetCells = [(3,8), (4,8), (3,9), (4,9)]
```

**Шаг 2: Зона атаки**
```
attackZone = {
    (2,7), (3,7), (4,7), (5,7),    // Соседи снизу
    (2,8), (5,8),                   // Соседи по бокам
    (2,9), (5,9),                   // Соседи по бокам
    (2,10), (3,10), (4,10), (5,10)  // Соседи сверху
}
```

**Шаг 3: Обратное преобразование**

Для клетки (3,7) из зоны атаки:
```
GetAnchorPointsForCell((3,7), UnitSize(2,2), Direction.North):
    Вариант 1: anchor = (3,7)   → займет (3,7), (4,7), (3,8), (4,8) ❌ конфликт с врагом
    Вариант 2: anchor = (2,7)   → займет (2,7), (3,7), (2,8), (3,8) ❌ конфликт
    Вариант 3: anchor = (3,6)   → займет (3,6), (4,6), (3,7), (4,7) ✅ может быть валидно
    Вариант 4: anchor = (2,6)   → займет (2,6), (3,6), (2,7), (3,7) ✅ может быть валидно
```

Собрав все варианты для всех клеток зоны атаки, получим кандидатов:
```
candidateAnchors = {(3,6), (2,6), (4,6), (5,6), ...}
```

**Шаг 4: Фильтрация**
```
Проверка через CanPlaceUnit(ignoreOccupied: true):
    (3,6) ✅ — в границах, свободно
    (2,6) ✅ — в границах, свободно
    (4,6) ✅ — в границах, свободно
    (5,6) ✅ — в границах, свободно

validPositions = [(3,6), (2,6), (4,6), (5,6), ...]
```

**Шаг 5: Приоритизация**
```
Текущая позиция: (3,0)

Сортировка по |deltaX|:
    (3,6): |3-3| = 0 ← наивысший приоритет (прямо вперед)
    (2,6): |2-3| = 1
    (4,6): |4-3| = 1
    (5,6): |5-3| = 2

Результат: [(3,6), (2,6), (4,6), ...]
```

**Итог:**
Слон пойдет на anchor (3,6), займет клетки (3,6), (4,6), (3,7), (4,7) и сможет атаковать врага с клетки (3,7), которая является соседней к (3,8) ✅

#### 6.4.6 Важные особенности реализации

**1. Fallback логика**
Если `CurrentTarget` отсутствует или невозможно получить клетки цели, алгоритм возвращается к простой логике (8 соседей вокруг позиции цели). Это обеспечивает совместимость со старой системой.

**2. Параметр ignoreOccupied: true**
При вызове `CanPlaceUnit(anchor, unitSize, direction, ignoreOccupied: true)` необходимо игнорировать текущую позицию атакующего юнита. Иначе юнит будет считать свою собственную позицию "занятой" и не сможет планировать путь.

**3. Конфликт имен**
В классе `AnimalMovement` есть поле `_direction` типа `Vector3`. Поэтому параметр метода `GetAnchorPointsForCell` назван `unitDirection`, чтобы избежать конфликта имен с полем класса.

**4. Использование HashSet**
`attackZone` и `candidateAnchors` используют `HashSet<Vector2Int>` для автоматического устранения дубликатов клеток.

**5. Приоритизация движения**
Приоритет отдается:
- **Первично:** Движению прямо вперед (минимальное отклонение по оси X)
- **Вторично:** Движению вперед по оси Y (ближе к верхней части поля)

Это обеспечивает более предсказуемое и визуально приятное поведение юнитов.

## 7. Особые случаи

### 7.1 Полет (Flying)

**Модификация алгоритма:**
- При проверке соседей игнорировать занятость промежуточных клеток
- Финальная клетка должна быть свободна
- **Вопрос:** Можно ли лететь над юнитом 2×2? (скорее всего да)

### 7.2 Додж (Dodge)

**Это не pathfinding!** Додж - это реакция на атаку:
- Срабатывает в момент атаки
- Ищет свободную клетку в приоритете: сторона → назад → любая
- Это логика боевой системы, а не pathfinding

### 7.3 Прыжок (Jumping)

**Модификация алгоритма:**
- Может "перепрыгнуть" через 1 занятую клетку
- Финальная клетка должна быть свободна
- **Вопрос:** Максимальная дальность прыжка?

### 7.4 Облепление (Куриц-боссы)

**Алгоритм:**
1. Найти ближайшего юнита игрока
2. Для каждой курицы найти ближайшую свободную клетку вокруг цели
3. Рассчитать пути для всех куриц одновременно
4. Резервировать клетки, чтобы курицы не шли в одну точку

## 10. Вопросы для обсуждения

### 10.1 Геймплейные вопросы

1. ✅ **РЕШЕНО: Направление (Direction) для юнитов**
   - **Решение:** Direction учитывается только для прямоугольных юнитов (1×2, 2×1)
   - Для квадратных юнитов (1×1, 2×2) поворот не важен - они симметричны
   - Это упрощает логику и улучшает производительность

2. ⏳ **ОТЛОЖЕНО: Размер орла**
   - Концепт-док не указывает
   - Решение отложено на будущее
   - Временно можно использовать 1×1 для прототипирования

### 10.2 Вопросы на будущее (специальные типы передвижения)

3. **Полет через юнитов 2×2?**
   - Можно ли лететь над слоном?
   - **Предложение:** да, можно

4. **Максимальная дальность прыжка кенгуру?**
   - Может перепрыгнуть 1 клетку? Или больше?
   - **Предложение:** 1 клетка (перепрыгивает соседнего юнита)

5. **Скорость орла "×0.3 в полёте"?**
   - Что это значит? Орел медленнее летает?
   - **Предложение:** Это про анимацию (медленнее двигается визуально)

6. **Велоцирапторы отбегают "на 1-4 клетки"?**
   - Рандомно от 1 до 4?
   - **Предложение:** Рандомно, зависит от оставшегося HP или просто случайно

## 14. Приложения

### 14.1 Примеры использования

**Пример 1: Простой поиск пути**
```csharp
var request = new PathRequest(
    startPosition: new Vector2Int(0, 0),
    targetPosition: new Vector2Int(5, 5),
    unitSize: UnitSize.Small,
    direction: Direction.North,
    movementType: MovementType.Walking,
    maxDistance: 10
);

PathResult result = _pathfindingService.FindPath(request);

if (result.Success)
{
    await _movementController.MoveAlongPathAsync(unit, result.Path, token);
}
```

```csharp
List<Vector2Int> reachable = _pathfindingService.GetReachableCells(

    unitSize: unit.Size,
    movementType: unit.MovementType
);

_visualizer.HighlightCells(reachable, Color.green);
```
