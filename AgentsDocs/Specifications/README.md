# Спецификации проекта Animal Merge

Эта папка содержит технические спецификации для различных систем проекта.

## Структура

Каждая спецификация пронумерована и описывает отдельную подсистему игры:

- `01_Pathfinding_System_Specification.md` - Система поиска пути и передвижения юнитов
- `02_Pathfinding_Test_Cases.md` - Тест-кейсы для системы поиска пути
- `03_Merge_And_Skills_System_Specification.md` - Система мерджа животных и навыков
- `04_Attack_And_Damage_System_Specification.md` - Система атаки и получения урона
- `05_Battle_System_Timings_Specification.md` - Тайминги боевой системы (состояния, движение, атаки, способности)
- `06_Balance_Sync_With_Concept_Doc.md` - **Реализовано (2026-08-01), кроме §2.8 и §3.** Расхождения баланса и мердж-скиллов с концепт-доком 3.0 (ClickUp «Heroes & Bosses»). Осталось: иглы ежа (блокер — арт), механика прогрессии (блокер — геймдизайн)

## Цель спецификаций

Спецификации помогают:
- 📋 Документировать геймплейные требования из концепт-дока
- 🏗️ Проектировать архитектуру систем
- 🤝 Обсуждать решения между программистом и геймдизайнером
- ✅ Валидировать реализацию
- 📚 Сохранять знания о проекте

## Как использовать спецификации

### Для разработчиков

**Перед началом работы с системой:**
1. ✅ Найди спецификацию для этой системы (см. список выше)
2. ✅ Прочитай разделы:
   - **Раздел 3** - Текущая архитектура (что уже есть)
   - **Раздел 5** - Предлагаемая архитектура (интерфейсы, классы)
   - **Раздел 10** - Вопросы для обсуждения (принятые решения)
   - **Раздел 11** - План реализации (что делать дальше)
3. ✅ Следуй архитектуре и принятым решениям из спецификации

**При добавлении новой функциональности:**
1. Проверь, покрывает ли спецификация эту функциональность
2. Если нет - обнови спецификацию перед началом работы
3. Обсуди изменения с командой

**После реализации:**
- Обнови статус задач в разделе 11 (План реализации)
- Если что-то изменилось - обнови спецификацию

### Для Claude Code (AI ассистент)

Спецификации интегрированы с Claude Code через `.claude/CLAUDE.md`.

**Workflow для Claude:**
1. При работе с системой - сначала читать спецификацию
2. Следовать архитектуре и решениям из спецификации
3. Не предлагать изменения, противоречащие спецификации
4. При неясностях - спрашивать у пользователя

**Пример:**
```
Пользователь: "Добавь GetReachableCells в pathfinding"

Claude:
1. Читает 01_Pathfinding_System_Specification.md
2. Видит в разделе 11: "Реализовать GetReachableCells()"
3. Читает раздел 6.3 - алгоритм GetReachableCells (BFS)
4. Реализует согласно спецификации
```

## Формат спецификации

Каждая спецификация содержит:

1. **Обзор** - краткое описание системы
2. **Геймплейные требования** - что система должна делать (из концепт-дока)
3. **Текущая архитектура** - анализ существующего кода
4. **Требования к новой системе** - технические и функциональные требования
5. **Предлагаемая архитектура** - интерфейсы, классы, компоненты
6. **Алгоритмы** - описание ключевых алгоритмов
7. **Особые случаи** - нестандартные ситуации
8. **Визуализация** - отладочная и игровая визуализация
9. **Интеграция** - взаимодействие с другими системами
10. **Вопросы для обсуждения** - неясные моменты
11. **План реализации** - этапы разработки
12. **Метрики успеха** - критерии качества
13. **Риски** - потенциальные проблемы и их решения
14. **Приложения** - примеры кода, диаграммы

## Процесс работы со спецификацией

1. **Черновик** - создается для обсуждения
2. **Обсуждение** - программист и геймдизайнер обсуждают вопросы
3. **Согласование** - спецификация утверждается
4. **Реализация** - разработка по спецификации
5. **Обновление** - спецификация обновляется при изменениях

## Принципы разработки

При создании спецификаций следуем:

- **Clean Architecture** - разделение на слои (Presentation, Application, Domain, Infrastructure)
- **SOLID принципы** - для гибкой и поддерживаемой архитектуры
- **Dependency Injection** - все зависимости через Zenject
- **Async/Await** - для асинхронных операций (вместо корутин)
- **Microsoft C# Coding Conventions** - единый стиль кода

Подробнее см. `.claude\CLAUDE.md`
