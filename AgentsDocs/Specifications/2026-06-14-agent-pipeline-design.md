# Agent Pipeline Design — /feature

## Цель

Системный пайплайн, который берёт краткое описание фичи и доводит её до готовой реализации: скомпилированный код, чистая Unity Console, пройденное архитектурное и игровое ревью, обновлённая база знаний.

## Определение "готово"

- Код написан и компилируется без ошибок
- Unity Console чистая (нет errors/warnings)
- Реализация соответствует оригинальной задаче и дизайн-документу (если был указан)
- Архитектурное ревью пройдено (Clean Architecture, Zenject, UniTask, код-стайл)
- Игровое ревью пройдено (логика, баланс, соответствие контексту игры)
- База знаний обновлена (Knowledge/Index.md)

## Команда агентов

### Вход: `/feature "краткое описание + контекст"`

### Оркестратор: `skills/feature/SKILL.md`

Тонкий координатор — не пишет код, только передаёт результат одного агента следующему. Поддерживает контекст-водопад: каждый агент получает только то что ему нужно.

### Агент 1: `agents/planner.md`

**Задача:** декомпозиция фичи в конкретный план реализации.

**Получает:** описание задачи + путь к дизайн-документу (если есть).

**Изучает перед планированием:**
- `Knowledge/Index.md` — текущее состояние проекта
- `CLAUDE.md`, `AgentsDocs/ProjectArchitecture.md`, `AgentsDocs/ZenjectPatterns.md`
- Релевантные спецификации из `AgentsDocs/Specifications/`
- Ключевые файлы затронутых модулей (интерфейсы, инсталлеры, фасады)

**Выдаёт:** пошаговый план с конкретными файлами, паттернами, зависимостями. Использует `ce-plan` skill.

**Контекст:** только задача + изученный контекст. Не знает о предыдущих разговорах.

### Агент 2: `agents/implementer.md`

**Задача:** реализация кода по плану или применение findings из ревью.

**Получает:** план от planner (или findings от reviewer) + указатели на нужные файлы.

**Выдаёт:** написанный код. Использует `ce-work` skill.

**Правила:** строго следует CLAUDE.md — Zenject, UniTask, Clean Architecture, C# naming.

**Контекст:** только план/findings + релевантные файлы.

### Unity Console Check (оркестратор)

После implementer — оркестратор читает Unity Console через UnityMCP. Если есть ошибки — возвращает implementer с конкретным списком ошибок. Повтор до чистой консоли (максимум 2 итерации).

### Агент 3: `agents/game-reviewer.md`

**Задача:** ревью изменений с двух сторон: технической и игровой.

**Получает:** список изменённых файлов + оригинальная постановка задачи.

**Выдаёт:** список findings с severity (critical/warning/suggestion).

**Техническое ревью:** вызывает `ce-code-review` skill.

**Игровое ревью:** вручную проверяет соответствие задаче, баланс, механики AnimalMerge, мобильную производительность.

**Контекст:** только изменённые файлы + задача.

### Финальная фаза (оркестратор)

Findings от game-reviewer передаются implementer:
- **critical** — implementer обязан исправить
- **warning** — исправляет если не меняет scope
- **suggestion** — выводится пользователю, не применяется автоматически

После правок — финальный Console check.

### Агент 4: `agents/knowledge-updater.md`

**Задача:** обновление базы знаний после завершения пайплайна.

**Получает:** summary реализованной фичи — что сделано, какие решения приняты, какие файлы изменены.

**Выдаёт:** обновлённый `Knowledge/Index.md`, опционально запись в Obsidian vault.

**Использует:** `update-knowledge` skill + `obsidian:obsidian-cli` (для архитектурных решений).

**Контекст:** только summary.

## Пайплайн

```
/feature "описание"
    │
    ├─► [planner]          контекст: задача + Knowledge/Index.md + docs + код модулей
    │       │ план
    │       ▼
    ├─► [implementer]      контекст: план + нужные файлы
    │       │ код
    │       ▼
    ├─► Unity Console check
    │       │ (ошибки → implementer, макс 2 итерации)
    │       ▼
    ├─► [game-reviewer]    контекст: diff + задача
    │       │ findings
    │       ▼
    ├─► [implementer]      контекст: critical+warning findings + файлы
    │       │ фикс
    │       ▼
    ├─► Unity Console check ✓
    │       │
    │       ▼
    └─► [knowledge-updater] контекст: summary фичи
            │
            ▼
         DONE → отчёт пользователю (✅ + ⚠️ suggestions + 📋 файлы)
```

## Human Gate

Агенты действуют автономно. Пользователь проверяет результат после завершения пайплайна.

## Размещение файлов

```
.claude/
  agents/
    planner.md           ← планировщик
    implementer.md       ← реализатор (ce-work)
    game-reviewer.md     ← ревьюер (ce-code-review + игровой контекст)
    knowledge-updater.md ← обновление базы знаний
  skills/
    feature/
      SKILL.md           ← оркестратор
    update-knowledge/    ← существует, используется knowledge-updater
```

## Ограничения (не входит в scope)

- Нет автокоммита / PR
- Нет деплоя
- Тесты — только если явно указано в задаче
- ScriptableObject assets — не создаёт автоматически
